# Prompt A-29 — Integrate the embedding cache with compilation

Implement only Prompt 5, "Offline compiler integration and exact fingerprinting", from the current
`docs/step4.md` in the separate `OntologyService` repository. Prompts A-25–A-28 have supplied the
offline embedding text and cache primitives, strict configuration and evidence types, the explicit
refresh command, and injected matcher fusion. Read those prompts, the current guide, `AGENTS.md`,
Project Narrative rules, `src/compiler.ts`, `src/embeddings.ts`, `src/matcher.ts`, `src/model.ts`,
the shared entity-loading path, `ontology/config.json`, generated artifact shapes, and relevant
compiler, matcher, CLI, runtime, and MCP tests before editing. Adapt names and paths to the
repository as it exists; do not assume a later prompt has added documentation or runtime evidence.

This stage is the first allowed cache-consuming compilation stage. It integrates a committed cache
into deterministic offline compilation only. It adds no model call, endpoint access, refresh,
credential read, automatic cache repair, runtime cache loading, MCP tool, or CLI behavior change.

## Cache loading and validation

When `embedding.enabled` is `false`, do not require, stat, resolve, open, parse, hash, or otherwise
read the configured cache path. Preserve lexical matching, fingerprints, and generated bytes exactly
as the disabled behavior before this stage.

When it is `true`, load the committed cache through the Prompt A-25 validation primitives, using the
validated configured relative cache path rather than a duplicated literal. Before calling the
matcher, fail closed unless all of the following hold:

- the configured path remains a normalized path below `ontology/embeddings/` and resolves within
  the repository;
- the cache has the supported schema, exact configured model ID, version, and dimension, and every
  vector has the configured dimension, finite numeric components, and is non-zero;
- every source and canonical entity text actually used by matching has a cache entry whose key,
  stored text, and SHA-256 content hash exactly match the freshly calculated canonical text; and
- the cache digest is calculated successfully from the fully validated, exact inputs consumed by
  this compilation.

For a missing, unreadable, malformed, stale-text, incomplete, identity-mismatched, wrong-dimension,
non-finite, zero-vector, or digest-validation failure, stop before matching with an actionable
instruction to run `npm run ontology:embed` and commit the refreshed cache. Do not silently omit a
vector, use an old vector, downgrade to lexical matching, or refresh during compilation. A missing
entry is not the Prompt A-28 matcher fallback here: enabled compilation requires complete coverage.

Build the digest deterministically over only the consumed cache inputs: schema version; exact model
ID, version, and dimension; sorted used content hashes; and, for each used hash, the exact canonical
text and six-decimal rounded vector. Use stable serialization and a lower-case SHA-256 result. Do
not include unused valid entries: adding, removing, or reordering them must not change the digest,
fingerprint, mapping output, or generated artifact bytes. Cache-entry ordering must never affect a
successful compilation.

Pass only the resulting validated in-memory context, including exact content hashes and digest, to
the Prompt A-28 matcher boundary. The matcher must not receive a path or perform filesystem access.

## Fingerprint, provenance, and generated artifacts

For enabled compilation, make the validated embedding configuration and calculated consumed-cache
digest governed compiler inputs and include both in stable source-fingerprint material. A changed
used vector, text hash, model identity, dimension, weight, or maximum semantic-candidate setting
must therefore change the fingerprint. Keep disabled fingerprints byte-identical to the previous
lexical behavior.

Project the Prompt A-26 `embeddingProvenance` into both generated JSON artifacts with the exact model
identity, configured cache path, consumed-cache digest, weights, and maximum semantic-candidate
count. Let fused selected candidates carry the complete Prompt A-26 structured `embeddingEvidence`:
independent lexical, embedding, and combined scores; model; digest; and source and target content
hashes. Validate these serialization boundaries and preserve deterministic property and collection
ordering. Do not add placeholders in disabled or lexical-fallback output.

Embedding scores and evidence are compilation provenance, not OWL reasoning. Do not add procedural
embedding assertions, inferred triples, OWL axioms, SHACL constraints, or an `owl-inference` claim.
Preserve the existing OWL and SHACL semantic model except for already governed serialization needed
to retain ordinary mapping facts; generated JSON is the evidence location for this stage.

Extend `ontology:check` through the normal deterministic recompile-and-compare path. With enabled
configuration, it must load and validate the same committed cache and report artifacts stale when a
consumed cache input changes. It must never refresh, write a cache, or reach a network endpoint.

## Tests and no-I/O boundaries

Add focused offline tests using the repository's existing test framework. Cover:

- disabled compilation and `ontology:check` with a missing cache path, proving neither reads it and

## Acceptance criteria and verification

- Disabled mode neither requires nor reads a cache and remains byte-identical to lexical
  compilation.
- Enabled mode validates path, model, dimension, full entity coverage, canonical text/content
  hashes, numeric vectors, and consumed-cache digest before matching; every failure is closed and
  actionable.
- Validated configuration and the consumed-cache digest govern the source fingerprint; generated
  JSON contains deterministic compilation-level and per-candidate evidence without claiming OWL
  inference.
- Reordered cache entries and repeated equivalent compiles are byte-identical; used changes make
  artifacts stale, while unused valid cache entries have no effect.
- Compilation, checking, runtime, and MCP remain offline; refresh stays the only network-capable
  embedding route.

Run `npm run check`, the focused compiler, matcher, stale-artifact, and no-I/O boundary tests, and
`git diff --check`. Run the deterministic compile/check evidence twice. Inspect the generated-
artifact diff and explain each expected enabled-fixture change; the committed disabled configuration
must leave `ontology/compiled/` without a diff. Commit locally with the focused message
`Integrate embedding cache with compilation`. Do not push.
