# Prompt 38 — Add embedding configuration and evidence

Implement only Prompt 2, "Configuration, types, and evidence", from the current `docs/step4.md`
in the separate `OntologyService` repository. Prompt 37 has already supplied the offline text,
hash, vector, and cache primitives. Read the current guide, `AGENTS.md`, `README.md`,
`docs/architecture.md`, `docs/registering-systems.md`, `CONTRIBUTING.md`, `Narrative.md`, the
current `src/model.ts`, `src/compiler.ts`, `src/matcher.ts`, `ontology/config.json`, compiled
artifact shapes, and relevant compiler and matcher tests before editing. Adapt names and paths to
the repository as it exists; do not assume a later prompt has added cache loading, refresh, or
embedding scoring.

This stage makes the future embedding contract explicit and validates it. It must not consume an
embedding cache, calculate an embedding score, alter lexical matching, rank candidates differently,
change a disposition, add a network client or refresh command, or add cache-consuming compiler,
runtime, CLI, or MCP integration. The normal committed configuration remains disabled and must
retain byte-identical compiled artifacts and lexical results.

## Configuration contract

Extend the source `CompilerConfig` and committed `ontology/config.json` with this exact disabled
default. Do not substitute a provider endpoint, secret, or environment value for this identity.

```json
"embedding": {
  "enabled": false,
  "model": {
    "id": "text-embedding-3-small",
    "version": "2024-01-25",
    "dimension": 1536
  },
  "cachePath": "ontology/embeddings/cache.json",
  "weights": {
    "lexical": 0.65,
    "embedding": 0.35
  },
  "maxSemanticCandidates": 5
}
```

Extend `validateConfig` (or its extracted, exported equivalent) to validate the complete config
shape before compilation. Reject unknown keys at the root, `embedding`, `model`, and `weights`
levels; do not silently ignore misspellings. Require both existing threshold fields and the
embedding object; `enabled` must be a boolean; model ID and version must be non-empty trimmed
strings; dimension and `maxSemanticCandidates` must be positive safe integers; and `cachePath`
must be a non-empty normalized relative `.json` path below `ontology/embeddings/`, without an
absolute path or traversal segment. Do not read that path in this stage.

Require lexical and embedding weights to be finite, non-negative numbers no greater than one. Their
sum must be one within a documented `1e-12` floating-point tolerance. Reject `NaN`, infinities,
negative or excessive weights, and every missing, extra, or invalid nested field. Continue to
validate the existing threshold relationship and reject non-finite threshold values too.

Keep the new configuration available to future offline compilation work, but do not make disabled
mode rewrite an existing compiled schema, source fingerprint, or generated bytes. In particular,
do not serialize disabled embedding configuration or empty embedding metadata into `ontology.json`
or `mapping-review.json`; do not compile merely to introduce such fields. Later enabled-mode
integration owns any deliberate fingerprint and generated-artifact change.

## Typed evidence contracts

Define exported, structured types rather than encoding this information in `reasons`. Add an
optional `embeddingEvidence` field to `MappingCandidate`. Its exact fields are `lexicalScore`,
`embeddingScore`, `combinedScore`, `model`, `cacheDigest`, `sourceContentHash`, and
`targetContentHash`. When it is present, require all of:

- finite lexical, embedding, and combined scores in `[0, 1]`;
- model ID, version, and positive integer dimension;
- a lower-case SHA-256 cache digest;
- lower-case SHA-256 source and target content hashes in `sourceContentHash` and
  `targetContentHash`.

Reject every unknown or missing candidate-evidence field whenever `embeddingEvidence` is present;
its optionality applies only to the evidence object as a whole, not to any member of that object.

The evidence is absent in this stage and must remain absent for disabled lexical candidates,
including manual, retired, unmatched, and review candidates. Do not create placeholder scores,
hashes, or cache digests.

Also define an exported optional compilation-level embedding provenance type, owned by both
`CompiledOntology` and `MappingReviewFile`, as `embeddingProvenance`, containing the exact model
identity, configured cache path, cache digest, weights, and maximum semantic-candidate count. Its
cache digest is a required SHA-256 only when provenance is present. This stage defines the contract
only: do not load, hash, or validate a cache to populate it. With embeddings disabled, omit the
provenance field entirely from generated output so the existing artifacts remain byte-identical.
Keep review summary counts separate from provenance; provenance is not a candidate count.

Use interfaces or types that make invalid evidence difficult to construct. Validate any evidence or
provenance crossing a serialization boundary. Reject unknown, missing, or malformed provenance
fields. When provenance is present, require its model identity, normalized cache path, weights, and
maximum semantic-candidate count to exactly equal the validated configuration, and validate its
model dimension, cache digest, finite weights, and candidate count by the same rules as config.
Use stable property and collection ordering for future round trips. Preserve existing public fields
and current lexical candidate serialization.

## Acceptance criteria and verification

- `embedding.enabled` is exactly `false` in the committed configuration, and model identity, cache
  path, weights, and maximum semantic-candidate count match the stated defaults.
- Complete strict validation rejects unknown, missing, malformed, non-finite, and semantically
  invalid configuration and evidence without cache or network access.
- Mapping candidates and compilation results have optional typed evidence/provenance contracts, but
  disabled output contains neither placeholders nor schema drift.
- Existing lexical matching and every compiled artifact remain byte-identical in disabled mode; no
  cache load, refresh, scoring, compiler behavior, runtime, CLI, or MCP surface changes.

Run `npm run check`, `git diff --check`, and the focused compiler/matcher regression tests. Inspect
the generated-artifact diff and confirm `ontology/compiled/` has no diff. Commit locally with the
focused message `Add embedding configuration and evidence`. Do not push.
